# Проверка MasterSetting 2.0 на Windows 10/11

Единственная неиспытанная платформа (на машине разработки только macOS). Этот
файл — пошаговая инструкция: что запустить на Windows и что прислать обратно,
чтобы я мог честно отметить платформу как проверенную.

**Всё делается на временных папках и тестовой карте. Реальные настройки не трогаем.**

---

## Промежуточный вариант: прогон под Wine (без Windows-машины)

Если Windows-машины под рукой нет, но есть Docker, можно прогнать **тот же
набор тестов под настоящим Windows-интерпретатором Python через Wine**
(подход тот же, что при сборке `.exe`):

```bash
docker build -t ms-winetest -f deploy/Dockerfile.wine-test .
docker run --rm -v "$PWD":/src ms-winetest
# Отчёт: deploy/windows-report/test-result.txt
```

Это **честная, но не полная** замена живой Windows: Wine не равно Windows, GUI
и поведение реальной камеры так не проверить. Зато это ловит
Windows-специфичные ошибки путей, `os.replace`, `GetVolumeInformationW`,
отсутствия POSIX-прав и старта tkinter.

> На машине разработки этот прогон пока не сделан: Docker Desktop установлен,
> но его движок не поднимается без первичной настройки вручную. Как только
> Docker рабочий — команда выше даёт дополнительное доказательство.

## Быстрый путь: автоматический скрипт (рекомендуется)

В папке проекта запустите двойным щелчком или из cmd:

```bat
deploy\verify_windows.bat
```

Скрипт сам: запускает автотесты, создаёт тестовую «карту» во временной папке,
прогоняет полный цикл (сохранить дважды → две версии, записать, проверить,
пропавшая карта), проверяет что видео не скопировано, и складывает всё в
`deploy\windows-report\` с итоговым **`REPORT.txt`**. Пришлите эту папку целиком.

Ожидаемо в `REPORT.txt`: `pytest код возврата: 0`, `Traceback в цикле: no`.

Ниже — та же проверка вручную, если хотите видеть каждый шаг.

---

## 0. Что понадобится

- Windows 10 или 11;
- Python 3.11+ (для запуска из исходников) **или** собранный `MasterSetting.exe`;
- кардридер и **тестовая** SD-карта (не боевая);
- папка с исходниками `MasterSettings`.

---

## 1. Запуск из исходников (быстрая проверка, ~10 минут)

Откройте **PowerShell** в папке проекта:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
pip install pytest
```

Примечание: канал подписанных обновлений использует `cryptography` (Ed25519).
Она уже входит в `requirements.txt`; без неё приложение честно откажется
принимать пакет обновления, а два теста подписи будут пропущены.

### 1.1 Автотесты

```powershell
pytest tests/ -q
```

Ожидаемо: **все тесты прошли** (`passed`), часть пропускается (`skipped`) — это
нормально:
- тесты прав POSIX (`chmod 0700`) на Windows неприменимы;
- тесты на реальных образцах FX3/FX3A пропускаются без файлов образцов.

Главное — **ноль `failed`/`error`**. Пришлите последнюю строку вывода.

Если что-то упало — пришлите целиком:
```powershell
pytest tests/ -q 2>&1 | Out-File -Encoding utf8 test-result.txt
```

### 1.2 Графический интерфейс

```powershell
python main.py
```

Должно открыться тёмное окно. Проверьте:

1. **Главный экран** — видны оператор, статус карты, две большие кнопки
   «Сохранить с карты» и «Записать на карту».
2. **F1** — открывается справка (локальный HTML, без интернета).
3. **F2/F3/F4** — открываются библиотека, пары, админ-панель.
4. Окно **растягивается** за край мышью, содержимое не обрезается.
5. **Кириллица** отображается без «квадратиков».

> Пришлите скриншот главного экрана и окна справки.

## 2. Проверка карты и обнаружения носителя

Вставьте **тестовую** карту в кардридер и выполните:

```powershell
python cli.py cards
python cli.py inspect --media "E:\"
```

(замените `E:` на реальную букву; `cards` покажет её сам).

**Ожидаемо:**

- `cards` находит карту (буква диска);
- `inspect` идёт по карте и показывает пути к файлам настроек;
- **видео (`.mp4`/`.mxf`) НЕ попадает в `settings_files`** — только в `all_files`
  с причиной «медиа/служебный формат».

> Пришлите вывод обеих команд.

---

## 3. Полный рабочий цикл (главное)

Используем временные папки, боевые данные не трогаем. Сначала создаём тестовую
«карту» готовым скриптом (он же проверяет, что медиа не считается настройками):

```powershell
$env:MS_BASE_PATH = "$env:TEMP\ms-test\base"
python deploy\make_test_card.py "$env:TEMP\ms-test\CARD"
```

Скрипт создаст два файла настроек (`FX3.DAT`, `FX3A.DAT`) и рядом «видео»
(`CLIP0001.MP4`, `CLIP0002.MXF`), которое копироваться **не должно**.

Затем (замените путь на вывод скрипта):

```powershell
$card = "$env:TEMP\ms-test\CARD"

# Сохранить с карты ДВА раза (проверяем: две версии, а не перезапись)
python cli.py save-version --operator "Иван" --camera SonyFX3 --preset "Основные" --media $card
python cli.py save-version --operator "Иван" --camera SonyFX3 --preset "Основные" --media $card
python cli.py versions     --operator "Иван" --camera SonyFX3 --preset "Основные"
# -> должно быть ДВЕ версии

# Записать обратно и проверить SHA-256
python cli.py write-version --operator "Иван" --camera SonyFX3 --preset "Основные" --card $card
python cli.py verify        --operator "Иван" --camera SonyFX3 --preset "Основные" --card $card
# -> "ok": true
```

**Что проверить глазами:**

| Проверка | Как убедиться | Ожидаемо |
|---|---|---|
| Видео не скопировано | `Get-ChildItem -Recurse $env:MS_BASE_PATH -Filter *.mp4` | пусто |
| Запись не затронула видео | файл `CLIP0001.MP4` на месте | есть |
| Пропавшая карта понятна | `python cli.py write-version ... --card "$env:TEMP\ms-test\GONE"` | ошибка, **без** `Traceback` |

> Пришлите вывод всех команд одним текстовым файлом.

## 4. Что прислать обратно

Одним архивом или текстом:

1. `test-result.txt` — вывод `pytest tests/ -q`;
2. `cards.txt`, `inspect.txt` — вывод команд из раздела 2;
3. `cycle.txt` — вывод команд из раздела 3;
4. 2–3 скриншота: главный экран, справка, любой мастер;
5. версия Windows (`winver`) и разрядность.
