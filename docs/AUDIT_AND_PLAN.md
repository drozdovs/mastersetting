## 3. ⚠️ Проблемы безопасности и данных, найденные при аудите

1. **Токен сервера в открытом виде.** В `~/.mastersetting/config.json` лежит JWT
   (`server_token`) и `server_url: https://mastersettings.app.dsdp.ru`, причём конфиг
   попал в тестовое состояние с `base_path` во временной папке. Токен нужно
   считать скомпрометированным, хранить секреты через системное хранилище
   (ТЗ, раздел «Безопасные операции»), и он **не должен** попадать в бекапы и логи.
2. **`base_path` в тестовой `tmp`-папке** — сейчас приложение «рабочее», но архив
   указывает в никуда. Нужен явный онбординг пути данных.
3. **`~/.mastersetting/agent_id.txt`** — остаток серверной интеграции.

## 5. План миграции старого `C:/setting`

Идемпотентная, с отчётом и возможностью отката. Реальный `C:/setting` на этой
машине отсутствует, поэтому миграция проектируется и тестируется на фикстурах.

1. **Бэкап.** Перед всем — копия `C:/setting` в `backup/<timestamp>/` с манифестом
   (список файлов + SHA-256 + размеры). Проверяемая: после копирования сверяем хеши.
2. **Инвентаризация.** Пройти `cameraman/<оператор>/<камера>/<дата_имя>/`, собрать:
   что импортируется, что пропускается, что имеет дубли имён/содержимого, что
   выглядит неполным (нет `.DAT`/`SONY0`-заголовка).
3. **Правило валидности пресета.** Папка НЕ считается пресетом только по имени —
   нужен хотя бы один файл настроек (по правилу модели, см. шлюз FX3).
4. **`_OLD` папки** (артефакт атомарной замены версии 1.9) обрабатывать отдельно:
   не импортировать вслепую, показывать в отчёте.
5. **`camera.txt`** — импортировать как начальный список камер, добавить FX3A.
6. **Новая библиотека.** Пишется **рядом**, старое не трогается до проверки.
   Путь данных настраиваемый, вне каталога установки.
7. **Откат.** Пока новая библиотека не подтверждена — старые данные нетронуты.

Главное правило ТЗ: действия называются «**Сохранить с карты**» (карта → библиотека)
и «**Записать на карту**» (библиотека → карта). Слово «Загрузить» для обоих запрещено.

### 6.1 Главный экран
- Текущий оператор (крупно), статус карты, статус последнего бекапа.
- Две большие операции: «Сохранить с карты» и «Записать на карту».
- Последние пресеты (короткий список).
- Кнопки: Библиотека, Пары FX3/FX3A, Помощь, Админ.
- **Не фиксировать 400 px** — окно масштабируется (`minsize` задан, без
  `resizable(False, False)`); так и у всех экранов, кроме модальных диалогов.

### 6.2 Сохранить с карты
`карта → выбор модели → выбор/создание пресета → просмотр файлов → «Сохранить
новую версию» → результат`. Пустые состояния, прогресс, отмена, итог.

### 6.3 Записать на карту
`оператор → модель или пара FX3/FX3A → выбранные версии → карта → просмотр
изменений → запись и проверка → результат`. Для FX3/FX3A — выбор **пары**, а не
одиночной модели.

### 6.4 Библиотека
Поиск, дерево оператор → камера → пресет → версии, детали версии (время, пути,
размеры, SHA-256, статус проверки, **исходная модель из заголовка файла**,
прошивка, носитель). Экспорт версии и удаление пресета — из этого же экрана.

### 6.5 Пары FX3/FX3A
Именованные пары («Основные», «Интервью»): явно выбранная версия FX3 + явно
выбранная версия FX3A. Пара может быть неполной. Версия не «уплывает» на самую новую.

### 6.6 Помощь
Отдельный локальный HTML без CDN, открывается на Windows и macOS, доступен как «Помощь».

### 6.7 Админ-панель
Операторы/модели, S3, бекапы, восстановление, обновления, журнал. Пароль с
безопасным хешированием и блокировкой перебора.

## 7. Что блокирует реализацию парной записи

### Что НЕ сделано и почему (честно)

1. **Парная запись FX3/FX3A — пути исследованы по реальным образцам, запись на
   камерах не проверена.** Реальные файлы `Settings/FX3/FX3.DAT` и
   `Settings/FX3A/FX3A.DAT` распознаны по сигнатуре `SONY0` (размер 47 549 Б,
   различаются 805 байт, строка модели `ILME-FX3` / `ILME-FX3A`). Рабочие скрипты
   пользователя `load.sh`/`load.ps1` пишут в `PRIVATE/SONY/SETTING/<МОДЕЛЬ>/CAMSET/<МОДЕЛЬ>.DAT` —
   **пути не конфликтуют**, оба комплекта ложатся в разные папки. Это проверено
   тестом `test_pair_write_with_real_samples_to_native_paths` (пишет оба образца
   на одну карту, оба остаются). Но ТЗ требует тест **с двумя камерами**: читает ли
   FX3 свою папку, игнорируя соседнюю. Пока этого нет — правила остаются
   `confirmed=False`, а пары в UI выключены. Подробно:
   `docs/FX3_PAIR_GATEWAY.md`.
2. **Проверка на Windows — автотесты пройдены в CI, живой запуск GUI ещё нет.**
   Полный набор прогоняется на `windows-latest`
   (`.github/workflows/build-windows.yml`, шаг «Run test suite on Windows»):
   **225 прошло, 13 пропущено, 0 упало**, сборка `.exe` завершается успешно.
   Тринадцать пропусков законны: 7 тестов только для macOS (обнаружение
   съёмных дисков), 4 — на реальных образцах FX3/FX3A (пути заданы для машины
   разработки), остальные — права POSIX. Осталось сделать **живой прогон
   интерфейса на компьютере комплектовки** (автотесты GUI идут без окна):
   пошаговая инструкция и скрипт `deploy/verify_windows.bat` —
   `docs/WINDOWS_VERIFICATION.md`.
3. **S3/обновления — только ядро**. Реальные ключи Timeweb и публичный ключ
   подписи не заданы: это данные владельца. Код и тесты готовы, включаются
   настройкой. Админ-панель умеет создавать и восстанавливать копии и проверять
   подписанный манифест обновления; доступ к этим действиям — только по паролю.
   «Подготовить пакет» проверяет подпись и хеш, делает страховочную копию данных
   и выкладывает проверенный установщик в папку обновлений — без тихого запуска;
   решение о запуске принимает администратор. Журнал попыток виден в панели.

### Проверки, выполняемые автоматически

Всего в наборе **238 тестов** (`pytest tests/ -q`), среди них сценарии п.4:
пропавшая карта, нехватка места с понятным сообщением, запрет копирования
видео/посторонних файлов, запись меняет только заданные файлы, совпадение
SHA-256 после записи, предупреждение о неполной паре, запрет двойной записи при
конфликте путей, сохранение старых пресетов при миграции, работа офлайн
(полный цикл сохранение→запись→проверка при заблокированной сети),
восстановление из копии со страховочным снимком, отклонение неверной подписи,
версия при повторном импорте в тот же день, удаление только по подтверждению и
экспорт без изменения библиотеки.

Отдельно — на **реальных образцах** FX3/FX3A: распознавание по сигнатуре,
отсутствие конфликта нативных путей и парная запись обоих комплектов на одну
карту в разные папки (`tests/test_acceptance.py`, раздел 17).

Дополнительно проверяются: состав снимка (видео/фото и временные файлы в копию
не попадают, конфигурация копируется **без секретов** — путь данных сохраняется,
а ключи/пароль нет), схлопывание быстрых изменений в один снимок, права каталога
данных (0700), запрет рабочей базы в каталоге установки, настраиваемый путь данных
(CLI `set-path` и кнопка «Путь данных»), идентификатор тома для защиты от подмены
карты, автопроверка обновления (офлайн/https/подпись), подготовка проверенного
пакета к ручному запуску с журналом, правила S3 (90 дней + versioning), безопасное
извлечение и определение съёмных дисков для macOS и Windows (логика WinAPI —
юнит-тестами), отмена и закрытие окна во время операции.
