# MasterSetting 2.0

Приложение для работы с настройками видеокамер: **автономный десктоп-агент**
(работает на Windows 10/11 и macOS).

- **«Сохранить с карты»** — копирует настройки камеры с SD-карты в личную
  библиотеку оператора.
- **«Записать на карту»** — берёт выбранную сохранённую версию и записывает её
  обратно на карту перед съёмкой.
- Работает **полностью офлайн** — сервер и интернет не нужны. Все данные
  (библиотека настроек, каталог, подсказки имён) хранятся локально.
- Переносит **только файлы настроек**. Видео, фотографии и служебные индексы
  карты не копируются.
- Распространяется как **портативная сборка**: распаковать архив и запустить
  `MasterSetting.exe` (Windows) либо `MasterSetting.app` (macOS).

## Статус проверки на платформах (честно)

| Платформа | Собрано | Запущено и проверено |
|---|---|---|
| **macOS** | ✅ `.app` + `.dmg` | ✅ **да** — приложение запускается, тесты проходят |
| **Windows 10/11** | ✅ скрипты сборки есть | ❌ **нет** — на этой машине только macOS |

Код кроссплатформенный (обнаружение носителей, `os.startfile`/`open`, пути по
ОС), но **живой прогон на Windows ещё не выполнялся**. Это единственная
непроверенная платформа; см. `docs/AUDIT_AND_PLAN.md`, раздел «Что НЕ сделано».

Пошаговая инструкция по проверке на Windows: **`docs/WINDOWS_VERIFICATION.md`**.
Быстрый путь — запустить `deploy\verify_windows.bat`: он сам прогонит автотесты,
полный цикл на тестовой карте и соберёт отчёт в `deploy\windows-report\REPORT.txt`.

## Архитектура

Единственный компонент — десктопное приложение:

```
┌──────────────────────────────────────┐
│             MasterSetting            │
│  GUI (CustomTkinter) + чистое ядро   │
│  локальная библиотека + каталог      │
└──────────────────────────────────────┘
```

Ядро **не содержит кода GUI** и тестируется отдельно; GUI только рисует и
вызывает `AppController`.

Структура репозитория:

```
mastersetting/      # чистое ядро
  settings_rules.py # ТОЛЬКО файлы настроек (сигнатура SONY0), защита от медиа
  versioning.py     # неизменяемые версии пресета
  safe_write.py     # temp → verify(SHA-256) → atomic → откат
  library.py        # сервис: plan/save/preview/write/verify, пары
  pairs.py          # именованные пары FX3/FX3A
  migration.py      # идемпотентная миграция C:/setting + проверяемый бэкап
  admin_auth.py     # PBKDF2-пароль, блокировка перебора, SecretStore
  s3_backup.py      # снимки данных, проверка, 90 дней, офлайн-отложка
  updates.py        # подписанный манифест обновлений
  catalog.py        # SQLite: журнал событий и статистика
agent/              # GUI: app.py, wizard.py, dialogs.py, controllers.py, theme.py
tests/              # pytest — 224 тестов
cli.py              # headless-CLI (только безопасные команды)
main.py             # точка входа GUI
deploy/             # PyInstaller spec, сборка .exe/.app, иконки
docs/help/          # офлайн-справка (без CDN и интернета)
```

> Устаревший движок `mastersetting/engine.py`, копировавший **корень карты
> целиком**, удалён по ТЗ вместе с командами CLI `save`/`load`.

## Локальное хранение

Ничего не зависит от сети:

- Архив настроек (настраиваемый, вне каталога установки):
  `%LOCALAPPDATA%\MasterSetting\setting` (Windows) или
  `~/MasterSetting/setting` (macOS/Linux). Можно переопределить через
  `config.json`, переменную `MS_BASE_PATH` или командой
  `python cli.py set-path --path …` / кнопкой **«Путь данных»** в админ-панели.
  Каталог установки и системный диск запрещены — там база пропадёт при обновлении.
- Старый архив 1.9 (`C:/setting`) не используется как рабочая база — он
  переносится миграцией в админ-панели после проверяемой копии.
- База каталога (SQLite): `%APPDATA%/MasterSetting/catalog.db` (Win) или
  `~/.mastersetting/` (Unix).
- Подсказки имён (камеры/операторы): `local_data.json` рядом с базой.
- События (журнал операций) накапливаются локально в SQLite.

Список камер и операторов собирается из локального каталога, файла
`camera.txt` и папок архива; всё, что пользователь вводит вручную,
дописывается в локальные подсказки и не «пропадает» между запусками.

## Сборка macOS .app и .dmg

Снимки экранов (к ТЗ п.1) пересобираются командой
`python deploy/render_screens.py` → `docs/screens/*.png` (на демонстрационных
данных, реальную карту не трогает).

Скрипт: `deploy/build_macos.sh`.

```bash
bash deploy/build_macos.sh          # соберёт dist/MasterSetting.app
bash deploy/build_macos.sh --dmg    # плюс dist/MasterSetting.dmg
```

Результат:

- `dist/MasterSetting.app` — приложение (~47 МБ);
- `dist/MasterSetting.dmg` — образ для переноса (~22 МБ).

Скрипт сам генерирует иконки (`deploy/make_icon.py`) и проверяет зависимости
(`tkinter`, `customtkinter`, `Pillow`, `PyInstaller`).

Запуск из терминала:

```bash
open dist/MasterSetting.app
```

> Приложение не подписано сертификатом Apple. При первом запуске macOS может
> предупредить о неизвестном разработчике — откройте
> «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть».

## Сборка Windows .exe (портативная)

Программа распространяется **только как портативная сборка**: распаковать
архив и запустить `MasterSetting.exe`.

### На своём Linux-сервере через Wine (без Windows-машины)

Скрипт: `deploy/build_on_server.sh`.

```bash
# Один раз — зависимости (Ubuntu 24.04):
dpkg --add-architecture i386
apt-get update
apt-get install -y --no-install-recommends \
    wine64 wine32:i386 winbind cabextract xvfb unzip wget

# Каждая сборка:
bash deploy/build_on_server.sh
```

Результат: `MasterSetting-windows-<версия>.zip` (папка `MasterSetting/`
с `MasterSetting.exe` внутри — распаковать и запустить).

Ключевые детали окружения:
- Windows-Python ставится как **python-build-standalone** (install_only) —
  обязательно **с tkinter**, иначе CustomTkinter не запустится
  (embeddable-Python tkinter не содержит — так был баг «приложение не стартует»);
- Wine ломает stdio Python при выводе в пайп, поэтому запуск идёт через
  псевдо-терминал (`script -qec`) — см. обёртку `wpy` в скрипте.

### Локально на Windows

```bat
deploy\build_agent.bat
```

Меры против ложных срабатываний антивируса:

1. **onedir**, не onefile; **UPX выключен**.
2. Version-info и манифест (уже в `deploy/`).
3. **Подпись кода** (`signtool`) — OV/EV сертификат.
4. Отправка сборки в Microsoft Defender как ложное срабатывание.

### Иконка приложения

Иконка генерируется скриптом `deploy/make_icon.py` (синяя SD-карта «MS»):

```bash
python deploy/make_icon.py     # -> deploy/icon.ico + icon.png + icon.icns
```

Она встроена в `.exe` (через `MasterSetting.spec`) и в `.app`
(через `MasterSetting-macos.spec`), а также в окно GUI.

## Безопасное развёртывание на компьютере комплектовки

Порядок для машины, где реально работают операторы:

1. **Распаковать сборку** в отдельную папку (например, `D:\MasterSetting` или
   `~/Applications/MasterSetting`). Установщик не нужен.

2. **Не хранить рабочую базу внутри каталога установки.** Библиотека настроек
   должна лежать отдельно и переживать обновление программы. Путь задаётся:
   - кнопкой **«Путь данных»** в админ-панели (самый простой способ);
   - командой `python cli.py set-path --path …`;
   - файлом `config.json` в каталоге данных приложения;
   - либо переменной окружения `MS_BASE_PATH`.
   Каталог данных: `%APPDATA%\MasterSetting` (Windows),
   `~/.mastersetting` (macOS). Системный диск и каталог установки запрещены.

3. **Сделать первую резервную копию** старого архива (`C:\setting`) через
   миграцию в админ-панели — она создаёт проверяемую копию **до** любых
   изменений. Старые данные не удаляются, пока новый архив не проверен.

4. **Проверить основные сценарии на тестовой карте:**
   - «Сохранить с карты» → появилась новая версия;
   - повторное сохранение в тот же день → **вторая** версия, старая цела;
   - «Записать на карту» → записан только нужный файл, видео не тронуто;
   - проверка SHA-256 после записи — совпадает.

5. **Настроить S3-резервные копии** в админ-панели. Ключи вводятся там и
   хранятся в системном хранилище секретов, а **не** в репозитории и **не** в
   обычном архиве копии.

6. **Пароль администратора** задать при первом входе в админ-панель. Он не
   хранится в открытом виде (PBKDF2-HMAC-SHA256, 200 000 итераций).

7. **Обновления** — отдельный канал с **подписанным манифестом**. Приложение
   проверяет подпись. В админ-панели есть **«Подготовить пакет…»**: подпись и хеш
   пакета проверяются, делается страховочная копия данных, а проверенный
   установщик выкладывается в папку обновлений. Запускаете его вы **вручную** —
   тихого автообновления нет. Все попытки видны в журнале обновлений.
   Никогда не запускайте исполняемый файл из бакета только по совпадению имени.
